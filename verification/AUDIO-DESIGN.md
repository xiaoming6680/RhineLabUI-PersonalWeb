# 声音重设计与验证

日期：2026-09-09。交付为原创配乐「Observatory / 观测室」、16 种程序合成音效、原片短音重构的逐字输入音效及实际终端集成。

## 依据和边界

查看本地《明日方舟》特别映像 [莱茵生命：访问] 的 6.76–40 秒画面联系表及现有逐帧记录；从原文件提取并测量同段声音。当前代理不能直接听辨音频，因此这些结果是画面观察、音轨数值分析与原创编配，不是对原曲旋律、乐器或 BPM 的听写。后续根据用户复刻逐字输入音效的要求，单独引入三个 38ms 原片短音，详见下文。

设定参照 [PRTS 收录的赫默档案](https://prts.wiki/w/赫默)、[克丽斯腾图鉴](https://prts.wiki/w/克丽斯腾)，以及项目既有 `reference/LORE-SOURCES.md`。将科研秩序、探索与独行感转译为精细脉冲、开放和声和稀疏动机，是本次声音设计的解释，并非官方对莱茵生命音乐风格的规定。

原片为 25 fps、48 kHz 双声道 AAC。`scripts/analyze-reference-audio.mjs` 将左右声道各取 0.5，解码为 24 kHz 浮点 PCM 后按视觉段落计算 RMS；输出见 `reference/audio-analysis.json`。验证段 11.12–22.76 秒约 −25 dBFS RMS，欢迎页 22.76–26.92 秒约 −15.92，阵列 26.92–30.68 秒约 −13.05。由此保留「克制验证 → 欢迎渐强 → 阵列展开 → 特写收敛」的动态结构；音乐不直接照搬原片的峰值响度。

## 编配

- 原创 72 BPM、4/4、16 小节、53⅓ 秒循环。72 BPM 是本次选择，不是原片测定速度。
- Dmaj9、Bm11、Gmaj9、Asus2 的开放和声，后半段以轻微配音变化回答；音符与休止直接写在生成脚本中。
- `atmosphere.ogg`：低饱和度、缓慢交叠的和声；`motif.ogg`：带衰减谐波的键音及交错延迟；`pulse.ogg`：稀疏低频呼吸与设备点击。
- 所有音符尾音和早期反射按环形缓冲叠加，三轨使用同一音频时钟启动、同一循环长度。场景切换只改变声部音量，不重启音乐。
- 浏览状态三轨比例为 0.9 / 0.72 / 0.65；详情为 0.72 / 0.36 / 0.12；模型查看为 0.8 / 0.24 / 0.28。启动段随原片时间 22.76、26.92、34.3 秒调整编配，约 0.9 秒过渡。
- 总输出有余量与压缩保护；抽取、欢迎、阵列和拆组时音乐短暂降低到 65%，约 0.9 秒恢复。

## 音效

| 操作 | 声音构成 |
| --- | --- |
| 窗口打开 / 关闭 | 180ms 轻空气上扫与低音抬升 / 130ms 下扫收束 |
| 标签切换 / 系统操作 | 52ms 无长共鸣的电子点击 |
| 启动标志 | 约 720ms 低频 D–A 和声逐层点亮，缓起音与轻空气声 |
| 整块文字显现 | 64ms 低音量的数据脉冲，每块一次 |
| 输入 | 原片截取的三个 38ms 短音轮替，保留原攻击与频谱 |
| 上下切档 | 1.68 kHz 主共鸣，短促清脆的薄玻璃轻碰 |
| 左右切列 | 稍低的玻璃碰击与很轻的第二次接触，按方向轻微左右定位 |
| 抽取 / 返回 | 较长、明亮的悬起余音 / 阻尼更强、收束更快的落定声 |
| 确认 | 640 / 960Hz 两次电子短音，作为授权及保存的标识 |
| 权限扫描 | 轻扫声与四次等距电子脉冲 |
| 欢迎 / 阵列 | 缓起音的开放和声 / 错开的薄玻璃碰击 |
| 特写读取 | 两次极短的同频电子脉冲 |
| 拆解 / 重组 | 三次渐高的玻璃分离声 / 渐低、短尾的接合声 |

键音至少间隔 24ms，以通过 25fps 输入的连续触发；切档与切列至少 55ms、其他同类事件至少 120ms；活动音效组限制为 10。冻结、倒退或跳转超过 0.3 秒不补播历史事件；离开启动时停止残留启动音效。

## 设置与生命周期

系统设置提供音效、音乐各自的开关与音量，自动保存。旧版本关闭界面声音的用户升级后继续保持静音；首次使用会在首次点击或按键后解锁声音。浏览器禁止无交互自动播放时，先点击页面，再重播启动即可听到完整流程。

隐藏页面、离开页面或全部静音时暂停音频上下文，音乐保留位置。重新开启串行等待先前的 suspend 完成，修复快速切换造成的 resume / suspend 竞争。音乐加载期间再次关闭不会迟到起播；载入失败可在下一次交互重试，音效独立工作。音量拖动只保存声音偏好，不触发画质重建。

## 2026-09-09 · 玻璃质感修订

用户进一步明确：交互对象像玻璃，声音应该清脆。当前音效按这一方向修订。使用约 1.2ms 接触起音和五组不等间隔共鸣频率；高阶共鸣更快衰减，最高模式限制在 8.5kHz 以下，加入很轻的 13ms 接触噪声。切档名义尾长 240ms，抽取 580ms，归位 220ms；指数衰减使实际主体更短。目标是薄玻璃轻碰的清亮感，属于合成音色设计，不宣称等同于真实玻璃录音。

保留原有输入节流与活动音效上限。试听页新增连续 40 次、间隔 55ms 的离线叠音检查，验证延长共鸣后仍有峰值余量。背景音乐的音符、声部与文件沿用上一版。

## 2026-09-10 · 改用参考网站录屏的声音

用户不喜欢原创三轨配乐，要求改用参考网站录屏 `音视频参考.mp4`（1920×1080、60 fps、239.17 秒、44.1 kHz 立体声 AAC）的声音：开头音效一比一复制，之后的背景音乐去除人声并无缝循环。此录屏是网站本身的操作记录，与原 PV 的时间关系为：录屏 0.50 秒第一帧白场 = 参考 6.76 秒（偏移 6.26 秒）；录屏 3.0 秒标志出现、16.5 秒欢迎页、20.75 秒阵列、24.5 秒抽取、28 秒特写，与既有 `bootMotion` 时间轴一致。

### 音轨结构（数值测量，非听辨）

- 0.70–15.30 秒为离散的开场音效，中间有多段完全静音；侧声道能量接近零，属单声道素材。
- 15.30–16.37 秒完全静音；16.37 秒起音乐进入并持续到片尾，侧声道能量约 −30 dB，属立体声混音。因此开场声音与音乐可以在 16.37 秒处无重叠地分开。
- 对音乐做起音包络的梳状匹配，得到恒定速度 121.0 BPM；按 30 秒分窗检查网格上的起音强度均远高于随机相位基线，全曲不变速。

### 处理

1. `scripts/build-bgm.py` 用 FFmpeg 解码为 48 kHz 浮点，自动定位「至少 0.2 秒静音后连续 10 秒不低于 −60 dB」的音乐起点。
2. 录屏 0.50 秒到音乐起点截为 `boot-intro.ogg`（15.88 秒，libvorbis q7），不做增益、去噪或裁剪。
3. 音乐起点之后的段落用 audio-separator 分离。三个模型的结果互相矛盾：BS-Roformer（`model_bs_roformer_ep_317_sdr_12.9755.ckpt`）与 Mel-Band Roformer（`vocals_mel_band_roformer.ckpt`）输出的伴奏与原声相关系数 1.000，被去除的成分比原声低约 24 dB，即认为全曲没有人声；MDX-Net（`UVR-MDX-NET-Inst_HQ_4.onnx`）则持续去除一个比原声低约 10 dB、音高在 160–250 Hz 间起伏、约半数帧有声的成分，并把 1–4 kHz 能量削去约 10 dB，前 6.7 秒几乎全部删除。代理不能听辨，无法判断该成分是人声还是主旋律合成器。当前交付采用 MDX 伴奏，并用 `--music-start 6.68` 跳过被删空的开头。2026-09-11 用户试听 A/B 片段后确认：原声有人声，MDX 版本去得干净，两个 Roformer 模型属于漏检。Roformer 伴奏仍保留在 `.tools/bgm/instrumental-roformer.wav`，不再作为候选。CPU 上 BS-Roformer 每块 65 秒（113 块），已改为 CUDA 版 torch 在 GPU 上推理，全曲 2 分 41 秒；MDX 在 CPU 上 4 分 50 秒。
4. 在伴奏上按节拍网格枚举「起点小节 → 终点小节」组合（16–64 小节），比较接缝后 8 拍与接缝前 4 拍的色度、MFCC 余弦距离及响度差；再用 4 ms 能量包络互相关把终点微调到 ±60 ms 内的最佳对齐。
5. 循环文件为伴奏从 0 到终点，终点前 0.5 秒与起点前 0.5 秒做等功率淡变，使 loopEnd → loopStart 处波形连续；峰值限制在 0.98。写出 `bgm-loop.ogg`（libvorbis q6）、`src/bgm-loop.ts` 与 `public/audio/bgm-source.json`。

选定循环：文件 81.32 → 160.66 秒（40 小节，79.34 秒），来自 MDX 伴奏并跳过被删空的前 6.68 秒；候选特征分 0.028，为全部候选中最佳，接缝包络互相关 0.567。解码后接缝样本差 0.004；接缝处的频谱变化量 11.9，与循环区间内普通小节边界的中位数 12.2 相当，即数值上接缝不比正常小节切换更突兀。候选排名与分数记录在 `bgm-source.json`；`.tools/bgm/seam-preview.wav` 为接缝前后各 4 秒的两遍拼接试听。

## 2026-09-11 · 入口按钮

带 `scene` 或 `time` 参数的评审页与自动化脚本跳过该入口；`scripts/check-startup-motion.mjs` 改为像访客一样点击按钮。无头 Edge 验证：按钮出现时 `ready` 仍为假，点击后进入开场（原片 9.09 秒时开场录音在播放，音频上下文 running），22.64 秒音乐进入，`?scene=archive` 直接进入档案；生产构建通过。

## 2026-09-11 · 阵列进场预热

用户反馈卡片推入画面时卡顿。`src/main.ts` 的帧循环在开场 21.9 秒之前不调用 `scene.update`，因此透射玻璃材质、阴影贴图、SSAO 与景深后期的着色器全部在阵列进场的第一帧编译，档案抬起时又触发第二轮。现在 `ArchiveScene.warmUp()` 在资源加载完成后、入口按钮出现之前执行：`renderer.compileAsync` 并行编译场景材质，再以 22.9 秒（阵列已进场）和 29.2 秒（档案完全抬起）两个参考状态各渲染一帧，最后复位为隐藏状态（reveal、scan、lift、detail、模型位置与外观全部还原）。这段时间加载页仍然覆盖画面，画布本身也处于透明状态。

## 2026-09-11 · 抽取时的镜头跳动

用户指出抽出文件、镜头准备推进时有小跳动。用 `rhine.seek` 以 0.05 秒步长采样 `stats().topLeft`（档案顶角的屏幕投影）：修正前 27.25 → 27.30 秒由 (518, 288) 跳到 (517, 298)，一帧 10 像素，之后再缓慢回到 295 附近；正是 `zoom` 从 27.3 秒开始推进的那一帧。原因在 `src/scene.ts` 的开场镜头：25.05–27.3 秒的承接段把锚点稳定在 (518, 288)，而 27.3 秒起的推进段以 (518, 296) 为起点，并用 `ease((shot − 27.3) / 0.5)` 从 0 重新混合到锚点。修正为推进段起点 (518, 288)、`288 + 42·extractionCamera`（1.25 秒后仍为 330，终点与后续 `close` 曲线不变），并直接采用锚点。修正后 27.30 秒步进为 0，27.40 秒起以每帧 1–3 像素平滑加速进入推进。检索脚本与对照页没有在 32–34 秒区间固定镜头的检查。
